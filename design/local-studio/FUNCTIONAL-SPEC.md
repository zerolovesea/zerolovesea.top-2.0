# local studio 开发前功能规格

功能现已接入本地应用，使用方式与当前实现范围见 [scripts/studio/README.md](../../scripts/studio/README.md)。下文保留开发前确定的规则和当时的连接测试记录。

确认日期：2026-10-22。本文补充并优先于 DESIGN.md 中较早的占位配置；本轮确定规则、核对代码并测试模型连接，不实现正式管理接口。

## 1. 编辑器直接拖放与粘贴图片

博文编辑区支持拖入本地图片、粘贴截图或剪贴板中的图片文件。系统读取图片数据，复制进当前文章的图片目录，并在操作位置插入 Markdown 图片引用。原图片不移动、不删除；不用手动去资源库上传。

- 新文档创建时分配稳定的文件标识和文件名。已有标题时可据此生成初始文件名；标题为空时使用时间与唯一后缀。上传图片后修改标题，不自动改变文件名或图片目录。
- 拖放使用编辑器的落点，粘贴使用当前光标/选区。上传开始时记录位置，异步上传完成后映射到当前文档位置，不能插到正文末尾或其他文档。
- 多张图片保持拖入/粘贴时的顺序。先显示临时占位，实际复制成功后替换为引用。任何一张失败，保留其他成功项，并允许单张重试；不插入不存在的目标 URL。
- 有文件名的图片保留规范化后的名称；无文件名截图使用 `image-<时间>-<唯一后缀>.png`。扩展名必须与真实格式相符。
- 同一篇文章内，图片内容相同则复用原文件；同名但内容不同生成新名字。禁止覆盖已有图片。
- 接受 png、jpeg、webp、gif，每张上限 20 mb。服务端校验真实类型、体积和路径边界，不信任客户端传来的文件路径或 MIME。
- 优先使用剪贴板里的图片二进制。复制网页上的纯图片链接、HTML 或本机 `file://` 文本，不当作已拿到文件内容，也不静默抓取远程 URL；无图片数据时提示使用拖入或选择文件。
- 图片复制成功即可出现在当前预览；正文尚未保存时图片也已在本地归档。撤销正文插入不删除图片，未引用图片留待显式清理，避免丢失文件。
- alt 文本可在插入后编辑，不强制每次粘贴弹出对话框。上传进度与失败信息贴近图片占位显示。

示例：

```text
src/content/writing/我的文章.md
public/_posts/我的文章/image-20261022-001.png
```

```markdown
![图片说明](/_posts/%E6%88%91%E7%9A%84%E6%96%87%E7%AB%A0/image-20261022-001.png)
```

新插入内容统一使用站点根路径 `/_posts/...`，每个路径段分别 URL 编码，避免英文页面把图片解释为 `/en/...` 下的相对资源。现有纯文件名图片继续兼容已有路径插件，不批量改写旧文。

## 2. 中英文文章共用图片目录与导航

同一篇内容按 **集合类型 + 相同文件名 stem** 关联，不用翻译后的标题关联，不为英文版创建另一套图片目录。

| 内容 | 文件 | 共享图片目录 |
| --- | --- | --- |
| 中文博文 | `src/content/writing/<stem>.md[x]` | `public/_posts/<stem>/` |
| 英文博文 | `src/content/writing-en/<stem>.md[x]` | 同上 |
| 中文想法 | `src/content/thought/<stem>.md[x]` | 拟新增 `public/_thoughts/<stem>/` |
| 英文想法 | `src/content/thought-en/<stem>.md[x]` | 同上 |

- 中英文扩展名可以不同，如中文为 `.mdx`、英文为 `.md`；同一语言不允许同时存在同 stem 的 `.md` 和 `.mdx`。
- 从任一语言上传图片，写入同一个目录，两种语言的资源选择器都能立即找到。翻译只翻译可见说明，不翻译文件名、路径或复制图片。
- 切换语言不改变图片 URL；网站实际文章路由是 `/<slug>` 与 `/en/<slug>`，不是假定的 `/writings/<slug>`。
- 管理端资源导航列出当前共享文件夹；站点图片查看器依据**当前语言正文中的图片出现顺序**生成上一张/下一张导航，不根据目录内所有文件排序。
- 中文和英文可以有不同的插图顺序、数量及 alt，但每张图片都解析到共享目录。重复引用同一张图按正文位置作为独立导航项。
- 支持点击放大、上一张/下一张按钮、键盘左右键和 Escape 关闭；显示当前序号/总数。首尾禁用越界操作，不自动循环；单张图片隐藏前后导航。按钮与键盘交互均可访问。
- 原型、真实本地预览、最终站点须使用一致的图集分组与查看器规则，不能只修管理端缩略图。
- 删除其中一个语言版本不删除共享图片。删除资源前检查两种语言及其他内容引用；有引用时阻止删除并列出位置。
- 文件改名是独立操作，整体列出中英文文件、图片目录与已有链接影响。标题编辑不隐式触发改名；已有外链不能静默失效。

**现有代码核对：** `remark-post-image-paths.ts` 已将 writing / writing-en 的纯文件名图片映射至相同 stem 的 `_posts` 目录。`rehype-image-gallery.ts` 已处理连续图片的图集。`writing-layout.astro` 已提供单图/图集放大查看，但没有前后切换；该部分需要在正式开发中补齐。中英文文章使用同一个 WritingLayout，可共用修正。MDX 中直接书写的 JSX 图片也需要检查，不假定 Markdown 图片插件会自动改写所有 JSX 属性。

## 3. LaTeX、Markdown 与 MDX

编辑区保留公式源码，排版预览和真实本地预览渲染公式。沿用项目已安装的 `remark-math`、`rehype-katex` 和 KaTeX 样式，不在管理端另建一套公式规则。

- 正式支持行内 `$...$` 与块级 `$$...$$`；金额中的字面 `$` 使用转义，代码块/行内代码中的内容不当作数学公式处理。
- 导入内容如使用 `\(...\)` / `\[...\]`，先检测并提示转换为受支持语法，预览转换差异；不声称现有链路天然支持所有定界符。
- 分式、求和、矩阵、aligned、上下标、希腊字母作为验收样例。长块级公式在自己的区域横向滚动，手机页面本身不横向溢出。
- Markdown 转 MDX 必须保留公式的反斜杠、花括号与换行；用实际 MDX 编译验证，禁止全局替换花括号或用字符串清洗破坏公式。
- 语法错误定位到段落/行，保留输入。正式保存前如果文档不能编译，应阻止写入正式集合，仍允许保留到独立草稿区。
- 翻译前提取并保护数学节点、代码、路径和 MDX 结构；译后恢复并逐项比对。公式本体不送去自由改写；公式外的解释文字可以翻译。
- 浅色与深色、中英文、Markdown 与 MDX 都需通过同组公式样例；预览与站点须得到一致结果。

**现有代码核对：** Astro Markdown processor 已注册数学插件，全局样式已引入 KaTeX CSS。现有设计原型的简化 `renderBody` 不是正式数学或 MDX 渲染器，不能用它替代验收。

## 4. 自定义 Claude 接口

协议选择 **Anthropic Messages**，不是 OpenAI Chat Completions。具体字段以用户提供的调用约定为准，结构也与 [Messages 官方文档](https://platform.claude.com/docs/en/api/messages/create)一致；服务商的模型别名以接口响应为准。

| 配置项 | 确定值 |
| --- | --- |
| 基础 endpoint | `https://one.iflytek.com/api/llm/console/chat` |
| 最终请求 URL | `https://one.iflytek.com/api/llm/console/chat/v1/messages` |
| 配置模型 | `claude-opus-4-8` |
| API 版本 | `2023-06-01` |
| User-Agent | `Brevia/1.0` |
| 密钥来源 | 本地服务环境变量 `STUDIO_LLM_API_KEY`；本文及项目不保存真实值 |
| 最小测试上限 | `max_tokens: 2048` |

拼接逻辑：去掉 endpoint 尾部 `/`；如果尚未以 `/v1/messages` 结尾，则追加该路径。保留 endpoint 原有 `/api/llm/console/chat` 前缀，不擅自简化为域名根路径，也不重复追加。

请求头：`Content-Type: application/json`、`User-Agent`、`anthropic-version`、`x-api-key`。请求体包含 `model`、`max_tokens` 和 `messages: [{role: "user", content: prompt}]`。密钥由本地服务添加，浏览器不直接携带密钥访问服务商。鉴权请求不自动跨域跟随重定向。

响应按 `content` 块解析文本，而不是读取 `choices[0]`。只消费文本块，不把 thinking / tool 内容写入文章；没有文本、JSON 不合法或状态失败都显示具体错误，并保留编辑内容。

### 本次真实连接测试

2026-10-22，使用用户提供密钥，仅发送固定的非私密连接测试提示，没有发送博文正文。

| 项目 | 结果 |
| --- | --- |
| HTTP 状态 | 200 |
| 耗时 | 约 1.86 秒 |
| 固定文本 | 正确返回 `CONNECTION_OK` |
| 配置模型 | `claude-opus-4-8` |
| 接口返回 model | `claude-opus-5` |
| stop_reason | `end_turn` |
| usage | 输入 23 tokens，输出 4 tokens |

用户已确认：**允许返回模型名不同，但必须展示差异。** 测试结果和每次翻译记录分别显示“配置模型”与“接口返回模型”；出现差异时提示服务商可能进行了别名映射，不更改用户的配置，也不声称验证了底层真实模型身份。

### 长文翻译与保存

- `2048` 仅作为当前测试/默认单次输出上限，不能假定足够翻译整篇文章。长文按文档节点分段；不在代码、公式、组件结构或表格中间随意截断。
- 分段生成期间显示进度，允许取消；出错保留已完成片段。只对超时、限流等可重试错误做有限重试，不自动改 endpoint、模型或协议。
- `stop_reason: max_tokens` 表示结果可能截断，不允许直接作为完整译文保存。提高上限或缩小分段后重新生成，不能静默接受残缺正文。
- 所有片段完成后，检查标题/摘要/正文、原始受保护节点、链接、图片引用、集合字段及 MDX 编译。任一检查失败，进入人工校对或重试；不覆盖现有英文文件。
- 用户确认后再原子写入英文集合，覆盖前保留上一版。中文内容和共享图片目录不变。
- 本次只验证连接与响应结构；长文翻译质量、截断恢复、限流、取消及结构保真尚未实测，属于开发验收项。

## 5. 开发验收顺序

1. 在已有/新建博文的光标中间粘贴截图、拖入多图；确认顺序、路径、重名与失败重试，原文件不被移动。
2. 同一 stem 的中英文交替上传和预览；分别从中文/英文正文放大图片，检查前后切换、序号、键盘、首尾及 alt。测试带中文、空格和特殊字符的文件名。
3. 用相同样例验证中文/英文 × Markdown/MDX × 浅色/深色；长公式手机不溢出，代码内 `$` 不误识别。
4. 用合成文章验证模型翻译保留公式、图片、链接、代码与组件；再测试长文分段、输出截断、超时和人工覆盖确认。
5. 最后验证正文写入冲突、备份/回收站与真实本地预览。所有实际写入与模型调用接入之前，当前设计原型仍明确标记为演示。
