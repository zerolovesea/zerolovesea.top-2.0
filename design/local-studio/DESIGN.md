已实现本地应用，启动命令为 `bun run studio`，也可双击项目根目录的 `start-studio.command`。当前使用说明与实现边界见 [应用说明](../../scripts/studio/README.md)。下文保留设计阶段的原型说明。

本地内容管理平台完整设计稿 · v2.0 · 2026-10-22

本轮交付为可点击的高保真界面原型与实施设计，不是已接入文件系统的管理平台。页面示例日期、统计、正文、翻译与状态均为设计数据；部分文章标题、字体、图片与组件名称取自项目。所有操作仅改变浏览器内存，刷新重置。

开发前已确认的图片拖放/粘贴、中英文共享资源与导航、LaTeX、Claude 协议及真实连接测试，见 [FUNCTIONAL-SPEC.md](./FUNCTIONAL-SPEC.md)。该规格优先于下文早期占位配置。界面原型本身仍不调用模型或写文件。

## 打开设计稿

在项目根目录运行：

```bash
bun design/local-studio/serve.mjs
```

打开 http://127.0.0.1:4322 。只监听本机地址，不接入线上部署，不写入文章、不调用模型。此目录不在 `public` 或 `src/pages` 中，不会成为站点公开路由。

验证本地只读服务：

```bash
bun test design/local-studio/serve.test.js
```

## 产品目标和方向

给单人作者一个每天可以打开的安静工作空间。管理现有 Markdown / MDX 文件，而不是把现有 Astro 网站迁移进另一套 CMS 数据库。最常用动作始终是：找到内容、修改、插图、预览、保存；翻译与组件按需出现。

视觉仅以 **Payload 应用的管理后台**为准。按用户最终确认，移除 Ghost / Sanity 的融合方向，也不套用 Payload 营销官网的页面风格。

已实际查看 [Payload 官方 Admin Panel 文档](https://payloadcms.com/docs/admin/overview)中的[浅色应用截图](https://payloadcms.com/images/docs/admin.jpg)与[深色应用截图](https://payloadcms.com/images/docs/admin-dark.jpg)。采用截图里的文字集合导航、薄竖分隔线、宽内容边距、灰底平面入口块、圆形加号、黑白操作控件和大标题。

浅色为默认，可在顶栏切换整个后台的深色主题。品牌使用博客现有猫咪 favicon（public/favicon-96x96.png）与首页 ZeroLoveSeA 文字标识，不复制 Payload 商标。顶栏、手机侧栏、作者头像、预览标识和浏览器标签页均复用博客资源。主视觉没有绿色品牌色、柔和圆角卡片或写作宣传文案。

## 主要流程

### 创建与修改博文

1. 从列表新建或打开一篇内容，编辑标题、摘要、正文与发布日期。
2. Markdown 模式编辑源内容；排版预览仅承担阅读检查。
3. 选择图片或组件，再打开本地预览检查。
4. 保存前展示实际目标文件；字段无效时停留在原处并定位字段。
5. 保存只更新本地内容。上线仍沿用项目已有的独立部署流程，后台不隐式 commit、push 或 deploy。

**正式实现的必要约束：** `title`、`description`、`pubDate` 对照实际 collection schema 校验；摘要允许空字符串。`readingTime` 为派生值；仅在实际变化时更新 `updatedDate`。保留未知 frontmatter 字段。保存时比对读取版本，发现外部改动时先比较，禁止静默覆盖。未保存离开或关闭窗口时提供保留、丢弃、取消选项。

**草稿边界：** 当前 schema 没有 `draft` 字段，不能仅在界面里加一个“草稿”标签就保证不公开。正式版未完成内容存入项目根 `.local-studio/drafts/`，保存进 collection 前明确确认。原型“待修改/已收录”仅演示工作状态，不等同线上发布状态。

### thoughts

右侧快速记录区输入正文，选择现有分类后保存。文件默认按 `YYYY-MM-DD-HH-mm` 命名，时区 Asia/Shanghai；同一分钟冲突时提示或追加序号。短内容不强制添加人为标题，沿用当前新建脚本的日期标题策略。中英文分类沿用项目已有分类映射。

想法也可以上传图片、插入组件、生成英文版。首次插入组件时转为 `.mdx`。正文与 `description` 的关系沿用现有脚本并在实际接入时明确同步策略，避免手动维护两份互相矛盾的内容。原型已提供独立编辑、翻译、预览入口；复杂的组件选择器最终与博文共用。

### 图片上传与归档

| 内容类型 | 原文件 | 图片位置 | 引用策略 |
| --- | --- | --- | --- |
| 中文博文 | `src/content/writing/<filename>.md[x]` | `public/_posts/<filename>/<image>` | 沿用现有插件或插入完整 `/_posts/...` URL |
| 英文博文 | `src/content/writing-en/<filename>.md[x]` | 与中文共享 | 不复制图片、不翻译路径 |
| 中文想法 | `src/content/thought/<timestamp>.md[x]` | 拟新增 `public/_thoughts/<timestamp>/<image>` | 插入完整 `/_thoughts/...` URL |
| 英文想法 | `src/content/thought-en/<timestamp>.md[x]` | 与中文共享 | 保留相同 URL |

当前 `remark-post-image-paths.ts` 只处理 writing 的纯文件名图片；thought 必须使用完整 URL，或在正式实现中明确扩展插件。不能假设写入某个图片目录后站点自然可读。

上传面板先选择归属，再显示目标路径，支持选择与拖放，输入替代文本后确认插入。限制 png、jpeg、webp、gif 和 20 mb；正式版本同时检查扩展名、MIME 与真实文件签名，拒绝脚本或伪装内容。重名自动生成新文件名，不覆盖原文件。文件名与目录片段做规范化、编码和边界验证；展示实际结果。

**标题不等于文件名：** 新建时从标题生成文件名；之后仅改标题不自动改路径。需要改名时独立显示中英文文件、图片目录与链接影响，并作为整体操作。当前原型使用标题演示路径，正式版本需独立保存不可变文档标识和文件名。

图片删除先展示引用位置。默认删除文章保留图片，禁止“顺便清理目录”破坏其他文章。资源详情的引用数在本稿为示例；正式版本从中英文所有 Markdown / MDX 引用中计算。

### 插入组件与 MDX 转换

编辑器 → 插入组件 → 选择形态 → 配置参数 → 插入当前位置 → 自动补充 import → 标记 `.mdx` → 预览 → 保存。

正式版在正文光标位置插入，不固定追加到文末。解析 frontmatter 和 ESM import，合并已有同源导入、避免重复符号与重名别名冲突；保留原正文与字段。先生成新文件并校验能编译，再原子替换，成功后移除旧扩展名文件，避免 `.md` 与 `.mdx` 同时进入集合。失败回滚并保持原文件。中英文各自按实际是否含组件决定格式，文件 stem 保持一致。

| 现有组件 | 真实能力 | 管理界面配置 |
| --- | --- | --- |
| `Highlight` | `color` + slot | 四种颜色、文字内容 |
| `Sidenote` | `id` + slot | 编号、补充说明；校验文内编号唯一 |
| `RevealQuote` | `teaser`、`quote`、`button?`、`subtitle?` | 显示内容、隐藏引言、可选按钮/副标题 |
| `DecisionToggle` | 固定演示内容 | 可插入整体，任意配置前需参数化 |
| `FlipCards` | 内容数组在组件内写死 | 同上，后续开放卡片字段 |
| `EnergyMeter` | 固定场景 | 同上，后续开放文案与刻度 |
| `DecisionForm` | 固定表单 | 同上，后续开放表单数据 |
| `AgentSimulation` | 固定模拟 | 同上，后续开放场景参数 |
| `CommitCompare` | 固定示例 | 同上，后续开放对照内容 |
| `EndCTA` / `FollowX` | 站点 cta 模块，需逐一核实实际 props | 后续作为“文章结尾”分组，不混入 9 个交互组件统计 |

`RevealQuote` 目前以 `set:html` 渲染 quote。管理平台需限制为纯文本并编码，或使用明确的安全 HTML 白名单；不可把模型输出和上传内容原样作为可信 HTML 执行。

本稿用短示意图表达组件形态，且只有现有公开参数可配置；不会把组件内部固定内容伪装成已开放参数。原型 import 拼接和末尾追加仅用于操作演示，不是生产转换算法。

### 大模型翻译

1. 设置服务商协议、接口地址、模型名及密钥环境变量名。用户已指定自定义 Claude / Anthropic Messages，详细配置与已确认的模型名差异策略见 FUNCTIONAL-SPEC.md；不写死未经验证的价格和底层模型身份。
2. 在文章/想法中打开翻译，显示中文原文与英文目标路径。
3. 生成阶段允许取消；错误可重试。原文和上一次人工编辑始终保留。
4. 标题、摘要和正文分别审核。保留代码、公式、链接、路径、import 与 JSX 结构，只翻译可见文字及适当的语义字段。
5. 对目标 collection schema 和 MDX 结构校验。缺失片段、损坏代码或组件时禁止保存并定位问题。
6. 确认新建或覆盖英文版本。覆盖先备份，中文保持原样。批量翻译逐篇生成并审核，失败不阻塞已完成项目。

密钥只由本地服务从环境变量读取，不放进客户端存储、请求日志、Markdown、Git 或导出包。点击生成前明确提示原文会发送到用户配置的服务商。设置“测试连接”不自动带上全文。正式版本还需考虑超时、取消、额度不足、429 限流、无效响应与部分成功。

原型使用固定英文示例和短暂加载状态，包含可触发的连接失败状态，不进行真实网络调用。中文示例正文与译文不保证逐段对应。

### 本地预览

原型提供桌面/手机布局示意与深色主题检查，不能编译 Astro 或执行真实 MDX。正式版复用站点现有 WritingLayout / ThoughtsLayout，准确呈现字体、目录、数学公式、代码块、图集、侧注和交互脚本。

保存后的真实页面可使用本地 dev server。未保存预览必须使用隔离的临时工作目录/独立预览进程，不能把草稿悄悄写进正式 collection。用文章 ID 映射正确的实际路由，不假定管理端路径即站点 URL。预览服务未启动时展示启动入口和错误输出，保留编辑器内容。

### 删除与恢复

删除对话框展示标题、集合、是否包含英文版本与图片保留规则。默认只移动所选语言的内容，删除中英文关联版本需显式选择；图片独立保留。文件移动到 collection 外的 `.local-studio/trash/`，附原始路径和删除时间。

恢复到原位置；已有同名文件时弹出冲突处理，不覆盖。清空回收站要求输入“清空”。原型模拟列表删除与恢复，英文影响范围勾选仅展示设计；不实际维护译文文件或删除图片。

## 响应式与可访问性

桌面 1200px 以上采用固定 230px 侧栏，编辑区配 245px 属性栏。1000px 以下属性栏和配置面板转为下排。700px 以下侧栏变为带可访问名称的图标导航，翻译双栏改上下堆叠，thought 输入区下排。表格只在自己的容器内横向滚动，页面本身不横向溢出。

使用语义按钮、表格、表单标签、`aria-current`、dialog、跳转链接和可见焦点。图标导航保留 title 和无障碍名称；状态除颜色外有文字；提示为 live region。正式版需把小尺寸控件扩大至合适触达面积，按内容面板提供焦点管理，并在屏幕阅读器和真实移动设备上确认。

## 实施范围与顺序

本轮仅增加本设计目录中的独立文件。未新增依赖、未改变 Astro 页面、现有内容、图片处理插件、构建配置或线上部署。工作区原有未提交的文章新增/删除保持原样。

后续以本地 sidecar 管理服务接入，复用现有内容目录、分类映射与组件入口，先完成文件读取、校验、版本检查和原子保存，再接入图片和 MDX 转换，随后接模型翻译与真实 Astro 预览。仅绑定 loopback；实际写操作需本地会话校验、Origin 检查与明确的路径白名单，防止其他网页调用本机服务写文件。回收站、临时预览、模型配置和备份均位于 collection 外，并在实际引入时配置 Git 忽略。
